# 角色与任务交接

用分析师与开发者两个顺序步骤，追踪原始约束和中间分析怎样进入代码生成。

## 起点与运行

使用课程 Python 3.11 或 3.12 环境，从仓库根目录安装依赖，并按[模型配置](../../README-DEEPSEEK.md#setup)设置 `OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_API_KEY`：

```bash
python -m pip install -r chapter7/cot_workflows/requirements.txt
python chapter7/cot_workflows/example3.py
```

任务与读数在 [example3.py](example3.py) 中提供：`18、21、24` 的平均值为21，平均值大于等于阈值时提醒。程序先请求分析，再把分析结果交给开发者；角色名称本身不会创建独立长期运行的智能体。

## 改变一个边界条件

保持读数、模型和交接方式不变，只将原任务阈值从20改成21。先预测边界结果，再核对开发者是否收到原任务与分析结果，生成代码是否仍使用“大于等于”。

在本地副本中运行生成的函数和断言，检查平均值等于阈值时是否提醒。模型输出了代码与代码实际执行是两个步骤；如果生成代码不可执行，保留错误并指出交接或实现中的缺口。

完成后分别标出原始任务、分析师输出和开发者输入，说明程序传递了什么，原始约束有没有被角色描述或中间总结覆盖。
